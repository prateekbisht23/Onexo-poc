Architecture · OneXO sandbox-harness POC

Claude CLI in a microVM, every model call through the OneXO gateway

Shown: the “/login → OneXO (AI gateway)” path. The user signs in to OneXO once; the harness then fetches that user's own short-lived OneXO token from the POC's token broker and calls Kong /llm through a reverse tunnel, metered and policy-checked as that user. The other /login option, “Anthropic account”, sends calls to Anthropic directly on the user's own subscription.

Infra · required to run today

Make the path exist

  • OneXO "Login with OneXO" client onexo-poc-login-3b9d41 (seed script): PKCE, redirect localhost:8091/auth/onexo/callback, scope ai:i
  • Users need a OneXO role with ai:i and a tenant whose AI policy allows the served models; GitHub sign-in enabled
  • Bifrost provider + a Connectra fallback chain that resolves Claude CLI's default model names
  • EC2 GatewayPorts clientspecified; reverse tunnels -R 0.0.0.0:18000:localhost:8000 and :18091
  • ONEXO_LLM_URL / POC_URL_FROM_VM = the addresses a VM sees; ports closed in the security group
  • Egress lockdown (docs/egress-lockdown.md) — Anthropic-account logins need api.anthropic.com, so pick strict or permissive

Infra · to make it real

Shared / production

  • Private networking CubeSandbox → Kong (VPC peering / PrivateLink) instead of laptop tunnels
  • Real POC user sessions (today one stub user per browser); the login client's secret in the secret manager; HTTPS redirect URI
  • Kong /llm rate limit per user; longer SSE read timeout for long tool runs
  • Per-tenant AI policies + per-user budgets for the harness population
  • Decide: policy denials as 400, not 403 (proposal in OneXO feature/)

Code · where the call is wired

Touchpoints

  • auth/onexo.ts + /auth/onexo/callback: OneXO sign-in, tenant pick
  • auth/logins.ts keeps the user's token fresh, one refresh at a time
  • gateway/broker.ts serves /internal/gateway-token, storm guard
  • harness/claude-cli.ts sets ANTHROPIC_BASE_URL + apiKeyHelper
  • OneXO: x-onexo-fallbacks: off in Connectra + @bot/agent
